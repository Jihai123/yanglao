# 退休规划助手 V2 重构规格

版本：V2.0
日期：2026-08-28
目标：把当前“单页养老金计算器”重构为移动端优先、低门槛、结果透明、可持续扩展的“退休规划助手”。

## 1. 产品目标

V2 的核心不是增加更多字段，而是让普通用户在 3 分钟内回答三个问题：

1. 我什么时候可以停止工作？
2. 我什么时候可以领取基本养老金？
3. 按当前计划，到领取养老金时大约能领多少，期间还需要缴多久？

必须明确区分：

- `stopWorkAge`：停止工作年龄，可早于退休年龄；
- `contributionEndAge`：养老保险停止缴费年龄；
- `pensionClaimAge`：办理退休/开始领取基本养老金年龄；
- `statutoryRetirementAge`：渐进式延迟后的法定退休年龄；
- `earliestFlexibleRetirementAge`：政策允许的最早弹性退休年龄；
- `latestFlexibleRetirementAge`：政策允许的最晚弹性退休年龄。

禁止再把“提前停止工作”与“弹性提前退休”混成一个概念。

## 2. V2 首页

移动端第一屏只解决“用户来这里想干什么”。

主标题：

> 退休规划助手

副标题：

> 什么时候能退、养老金有多少、提前不工作要准备什么，一次算清楚。

四个主入口：

1. 我什么时候能退休？
2. 我正常工作到退休，每月能领多少？
3. 我想几年后不工作，养老金怎么办？
4. 我已经离职/灵活就业，后面怎么缴更合适？

次级入口保留：城乡居民养老测算。

首页禁止一次性展示完整养老金表单。

## 3. 交互原则

### 3.1 Mobile First

以 375–430px 宽度为第一设计目标。

- 单列布局；
- 每一步只问 1–2 个问题；
- 底部固定主 CTA：`下一步` / `查看结果`；
- 输入区域触控高度 >= 44px；
- 不允许横向滚动；
- 不在手机首屏展示公式、FAQ 或十几个字段。

### 3.2 渐进式披露

普通模式只问必要信息；专业参数放入“提高测算精度”区域。

用户不知道某项数据时必须允许继续，不允许因为不知道“个人账户累计储存额”而直接无法计算。

### 3.3 结果先回答问题，再解释公式

结果第一屏优先显示：

- 几岁停止工作；
- 几岁开始领养老金；
- 中间空窗期；
- 预计总缴费年限；
- 是否满足最低缴费年限；
- 预计养老金（精确输入时显示点估算；存在假设时显示区间）。

公式和参数说明放在结果下方。

## 4. V2 主流程

### Step 1：基础身份

- 出生年月；
- 人员类型：
  - 原法定退休年龄 60 周岁人员；
  - 原法定退休年龄 55 周岁女职工；
  - 原法定退休年龄 50 周岁女职工。

避免默认使用“干部/工人”这种普通用户不一定能判断的描述，可在帮助文本中解释。

### Step 2：当前养老状态

- 当前累计养老缴费年限；
- 当前养老保险个人账户余额：
  - 知道：填写金额；
  - 不知道：选择“不知道，先帮我估算”。

### Step 3：工作计划

- 计划几岁停止工作；
- 停止工作后养老保险：
  - 同时停止缴费；
  - 继续缴到某个年龄；
  - 一直缴到开始领取养老金。

### Step 4：领取养老金年龄

系统先展示：

- 法定退休年龄；
- 政策允许的最早弹性退休年龄；
- 最晚弹性退休年龄。

用户选择 `pensionClaimAge`。

系统必须结合目标领取年份的最低缴费年限再次判断是否具备按月领取资格。

### Step 5：养老金测算精度

两种模式：

#### 快速估算

适合不知道完整社保参数的用户。

输入尽量少：

- 当前养老缴费基数（月）；
- 大致缴费档位/平均缴费指数：60%、80%、100%、150%、200%、300% 或“不清楚”；
- 个人账户余额若未知，则以历史缴费与当前基数生成区间估算，结果明确标为“估算”。

快速模式禁止输出伪精确到分的金额，应输出合理区间，并显示影响区间的关键假设。

#### 精确测算

用户可提供：

- 当地最新养老金计发基数；
- 本人平均缴费指数；
- 当前个人账户累计储存额；
- 视同缴费/过渡性养老金相关参数（如适用）；
- 地方加发（如适用）。

所有地区参数必须带 `source / effective_date / updated_at` 元数据。没有可靠来源的地区不得自动预置为“准确值”。

## 5. 结果页

### 5.1 第一屏结论

示例：

> 按你现在的计划，50 岁停止工作，55 岁停止缴养老保险，60 岁开始领取养老金。

显示：

- 停止工作：50 岁；
- 停止缴费：55 岁；
- 开始领养老金：60 岁；
- 养老空窗期：10 年；
- 预计累计缴费：XX 年；
- 最低缴费要求：XX 年；
- 预计养老金：¥X,XXX–¥X,XXX/月（快速估算）或 ¥X,XXX/月（精确测算）。

### 5.2 时间轴

`现在 → 停止工作 → 停止缴费 → 开始领取养老金`

必须能表达三个年龄不同。

### 5.3 方案比较

默认比较：

A. 停止工作时同时停缴；
B. 停止工作后继续缴 5 年（不超过领取年龄）；
C. 一直缴到领取养老金。

比较：

- 总缴费年限；
- 是否达到最低缴费年限；
- 预计个人账户；
- 预计月养老金；
- 与当前方案相比增加/减少多少。

不要默认给出“哪个一定更划算”的结论，只展示差异和假设。

## 6. 准确性规则（P0）

### 6.1 渐进式延迟退休

政策依据：全国人大常委会《关于实施渐进式延迟法定退休年龄的决定》，2025-01-01 起实施。

- 原 60 周岁：每 4 个月延迟 1 个月，最终到 63 周岁；
- 原 55 周岁：每 4 个月延迟 1 个月，最终到 58 周岁；
- 原 50 周岁：每 2 个月延迟 1 个月，最终到 55 周岁。

### 6.2 弹性退休

满足最低缴费年限后：

- 可弹性提前，最多早于法定退休年龄 3 年；
- 但不得低于原法定退休年龄 60/55/50 周岁；
- 可在符合政策条件时弹性延迟，最长 3 年。

### 6.3 最低缴费年限

- 2029 年及以前：15 年；
- 2030 年：15.5 年；
- 之后每年增加 0.5 年；
- 2039 年及以后：20 年。

最低缴费年限必须按“实际开始领取养老金的年份”判断，不能错误使用原法定退休年份。

### 6.4 个人账户养老金计发月数

按国家统一计发月数表执行。

关键修复：

- 47 周岁对应 **208**，不是 207；
- 退休年龄按“周岁年龄”选择计发月数，禁止使用 `Math.round(ageMonths / 12)` 四舍五入；
- 例如 60 岁 7 个月不能因为四舍五入而直接按 61 周岁计发。

### 6.5 基础养老金

通用基础公式：

`基础养老金 = 退休时计发基数 × (1 + 本人平均缴费指数) / 2 × 累计缴费年限 × 1%`

个人账户养老金：

`个人账户养老金 = 退休时个人账户储存额 / 退休周岁对应计发月数`

过渡性养老金、地方加发属于地区/个人差异项，默认不得凭空估算成确定金额。

## 7. 当前版本必须修复的问题

1. 47 岁计发月数错误（207 → 208）；
2. 非整岁退休年龄计发月数使用四舍五入错误；
3. 当前页面“计划退休年龄”混淆停止工作和领取养老金；
4. 当前测算直接使用“当前累计缴费年限”，没有把未来继续缴费计入退休时累计缴费；
5. 当前个人账户余额没有按未来缴费继续积累；
6. 地区计发基数硬编码且缺少来源/生效日期，容易产生伪精确；
7. 不知道个人账户余额时无法完成测算；
8. 一屏输入项过多，手机操作成本高。

## 8. 技术重构建议

今天不引入 Next.js/Vue 等框架，避免增加部署变量。继续使用静态 HTML/CSS/JS，但拆分职责：

```text
index.html
assets/
  styles.css
js/
  policy.js       # 法定退休年龄、弹性退休、最低缴费年限、计发月数
  projection.js   # 未来缴费、账户累积、养老金预测
  scenarios.js    # 方案比较
  app.js          # wizard 状态与 UI
  storage.js      # localStorage 保存方案
  data.js         # 有来源和日期的地区参数（无可靠数据则为空）
tests_logic/
  pension_logic.py
  test_pension_logic.py
tests_e2e/
  ...
```

不得继续把 CSS、HTML、政策规则、业务计算全部堆在单个 40KB+ HTML 文件中。

## 9. 留存设计

V2 第一版使用 localStorage，无需账号系统。

保存：

- 上次输入；
- 当前退休方案；
- 最近一次结果；
- 参数/政策版本。

用户再次打开首页时优先出现：

> 继续我的退休方案

并展示：

- 计划停止工作年龄；
- 计划领取养老金年龄；
- 上次预计养老金区间。

## 10. SEO

SEO 不能绑架主交互。

首页首屏服务真实用户；FAQ、公式、政策说明、结构化数据放到页面后半部分。

保留核心搜索意图：

- 养老金计算器；
- 退休年龄查询；
- 延迟退休年龄；
- 提前退休养老金；
- 灵活就业养老金；
- 养老保险缴费年限。

## 11. 验收标准

### 逻辑

- 男 1965-01：法定退休年龄 60 岁 1 个月，退休时间 2025-02；
- 47 周岁计发月数 = 208；
- 60 岁 11 个月仍按 60 周岁计发月数，不得四舍五入到 61；
- 2030 最低缴费年限 = 15.5；2039 = 20；
- “50 岁停止工作、55 岁停止缴费、60 岁领养老金”可以独立表达和计算；
- 未来继续缴费必须增加累计缴费年限和个人账户；
- 不知道个人账户余额时仍能得到“估算区间”，但必须标明估算等级；
- 未满足最低缴费年限时不得显示“可正常按月领取”结论。

### UX

- 375px 宽度无横向滚动；
- 首页首屏不出现复杂表单；
- 任一步骤 <= 2 个核心问题；
- 用户可返回上一步且数据不丢失；
- 结果页第一屏无需理解专业术语即可得到结论；
- 所有估算结果均能看到“采用了哪些假设”。

### 回归

保留城乡居民养老基础测算能力，不因 V2 重构完全丢失现有入口。
