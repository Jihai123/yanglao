# V2 政策可信度与地区参数治理

日期：2026-08-28

## 目标

退休规划助手不能只“算出一个数字”，还要让用户知道：

- 哪些结论来自国家现行政策；
- 哪些参数来自参保地官方公开数据；
- 数据适用哪一年、什么时候发布；
- 哪些地区必须继续细分到城市 / 地区档次；
- 哪些数字是长期预测假设，而不是待遇承诺；
- 用户如何去官方渠道交叉验证。

## 三层可信度

### 1. 国家政策规则

直接进入规则引擎，要求来源为国家权威部门，且页面可打开原文。

当前核心来源：

- 全国人大常委会 / 国务院：渐进式延迟法定退休年龄决定；
- 人力资源社会保障部、中共中央组织部、财政部：《实施弹性退休制度暂行办法》。

国家规则用于：

- 渐进式法定退休年龄；
- 最早 / 最晚弹性退休范围；
- 2030—2039 最低缴费年限变化；
- 弹性提前、弹性延迟的最低缴费年限引用年份。

### 2. 地区参数

地区数值必须保存可审计元数据：

- `value` 或 `min/max/standard`；
- `year`；
- `current`：是否可作为当前年度输入校验依据；
- `published`；
- `issuer`；
- `url`。

缺少官方来源或无法确认是否为当前最新值时，不自动带入。

当前首批已核验：

- 北京：2025 养老保险待遇计算基数；2026 社保缴费基数上下限；
- 上海：2026 社保缴费基数上下限；2026 最新企业基本养老金计发办法；
- 江苏：企业职工基本养老保险实施办法；
- 湖北：2025 社保缴费基数官方三档地区结构。由于本次核验尚未找到 2026 新标准，2025 数值只做历史参考，不作为 2026 自动校验参数。

全国省级地区均可选择；未收录最新官方参数的地区进入 `manual` 模式，不借用其他地区数值。

### 2.1 省内城市 / 档次差异

禁止假设“一个省只有一个缴费参数”。

如果省级官方文件按城市、片区或档次发布不同参数：

- 省级数据标记 `needsSubregion: true`；
- 在 `subregions` 中保存城市 / 档次映射；
- UI 必须继续让用户选择城市或档次；
- 未选择具体档次前，不得自动使用某一档参数；
- 每个档次仍必须保存独立的适用年度和官方来源。

湖北当前作为第一组实现案例：

- 第 1 档：武汉市 / 省直；
- 第 2 档：黄石、十堰、襄阳、宜昌、荆门、随州、恩施；
- 第 3 档：荆州、鄂州、孝感、黄冈、咸宁、仙桃、天门、潜江、神农架。

后续广东等存在地区差异的省份也必须沿用这一结构，不允许为了 UI 简单而压成一个全省数字。

### 2.2 数据新鲜度

地区参数必须区分“已核验”和“当前年度可用”。

- `current: true`：可以用于当前年度输入范围校验；
- `current: false`：只能显示为历史 / 最近已核验参考，不用于当前年度输入校验，也不自动代入养老金金额；
- 页面必须同时展示参数年度和最后核验日期；
- 找不到当年新参数时，宁可降级为手填 / 估算，也不能把旧数据标成当前值。

## 3. 长期预测假设

以下内容不得显示为“政策精确”：

- 未来计发基数增长率；
- 未来工资 / 缴费基数增长率；
- 个人账户未来记账收益；
- 长期通胀；
- 未知个人账户余额的估算。

页面必须显示为规划预测，并允许用户查看假设。

## 页面呈现

### 首页

显示：

- `官方来源可核验`；
- `政策与数据已核验至 YYYY-MM-DD`；
- 最近一条与养老 / 退休相关的人社部官方动态；
- 可展开查看国家政策原文。

最新动态只作为信息展示，除非明确进入计算模型，否则标注“不直接改变本次金额公式”。

### 测算过程

在金额参数步骤增加“参保 / 退休地区”：

- 全国省级地区可选；
- 有省内差异时继续选择城市 / 地区档次；
- 已核验地区展示参数年份和官方来源；
- 只有 `current: true` 的缴费基数上下限才用于当前输入范围提示；
- 历史数值明确显示为历史参考；
- 有可靠官方待遇计算基数时，精确输入模式允许用户一键带入，但不强制覆盖用户输入。

### 结果页

增加“政策与数据依据”：

- 国家规则：政策来源；
- 地区参数：省份、城市 / 档次、年份、发布机构；
- 金额：规划预测标签；
- 最后核验日期；
- 人社部官方养老待遇测算服务交叉验证入口。

## 更新规则

1. 不在浏览器运行时抓取政府网站，避免 CORS、网站结构变化和不可审计数据直接影响计算。
2. 官方信息先进入受版本控制的 `js/sources.js` 注册表，经核验和测试后发布。
3. 任何地区自动数值必须附官方 URL 与适用年份。
4. 省内存在多档参数时必须建 `subregions`，不得取任意一档代表全省。
5. 新政策如果改变规则，先更新规则测试，再更新页面说明。
6. 纯新闻 / 工作动态不得直接改变金额计算。
7. 旧数据可以保留为历史参考，但不得标成“当前最新”。
8. 新增地区数据必须补来源注册表测试，至少验证官方域名、年份和 freshness 状态。
