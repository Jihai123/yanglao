# Bing 搜索曝光归零：Git 变更时间线与因果证据审计

日期：2026-10-09；对象：`https://yanglao.zhibeimao.com/`；范围：2026-09-10—2026-09-20。代码证据：`main` 历史、PR #9—#16、历史 index diff；站长数据：网站维护者 2026-10-08 已提交的 Bing Webmaster 截图。**本报告不构成 Bing 处罚、降权或任何特定部署故障的确定性判断。**

## 结论

**高置信事实**：9 月 13 日 PR #9 明显改变首页首屏文字和入口；9 月 14—15 日连续发布多个前端/后台变更；所查 `main` 提交历史未见 9 月 16—20 日的新提交；在 9 月 6 日 `05c964e` → 9 月 15 日 `5e3ced8` 的代码比较中，`index.html` 被修改，但 `robots.txt`、`sitemap.xml` 没有出现在变更清单；仓库默认分支的文件树中也没有 Nginx、Apache、Cloudflare 或部署配置文件。最后一点只意味着**仓库没有这些文件**，不意味着线上配置未变化。

**中置信嫌疑**：PR #9 弱化首屏“养老金/缴费年限/退休年龄”等与 Bing 历史关键词直接匹配的文字，属于可以开展受控实验的 SEO 语义线索，但**不足以解释所有查询同时断崖到零**。

**根因尚不确定**：没有 9 月中旬每日 query/page 细表、Bing 当时的排名变化、服务器真实部署时间及 Bingbot 历史访问日志；因此不能将相关性当作因果关系。已索引、实时抓取正常并不等于具体关键词必然有展示量。

## 3. 嫌疑点优先级

- **高：已确认的代码事实，不是根因**。PR #9 改 H1 与首屏、历史关键词曝光集中首页，以及 Bing 9/16 左右下降，均有记录。
- **中：首屏关键词匹配弱化**。可能降低“养老金计算器”等关键词相关性；对几十个关键词几乎同时归零的解释力度有限。仅通过后续控制变量验证。
- **中低：Bing search-serving/报告数据异常**。缺乏本站直接证据；同日其他站点个案只是线索，不能推广为平台级事故。
- **低：资源缓存、脚本加载差异**。代码有潜在缓存风险，但没有证明 Bingbot 遇到错误响应或索引中缺正文。
- **未核实（不是低风险）：实际部署与 CDN/服务端变化**。仓库不含服务器配置/历史访问日志，不得假定没有变更。

## 4. 最小取证清单（无需修改生产）

1. 从 Bing Search Performance 按日导出 2026-09-01—10-08 的 **Pages、Queries**，固定同一搜索市场、搜索类型、日期/时区，并对比前后相同关键词的曝光及排名；导出原始 CSV，不混合历史平均排名与当前排名。
2. 从服务器已存在的部署历史、Git HEAD/更新记录、Web 服务 access/error 日志和（如有）CDN 日志查真实上线时间；重点 9/12—9/20。只读方式提取 Bingbot 请求的状态码、路径、时间、响应大小、User-Agent，以及同期 `/` 的 200/301/403/429/5xx 分布。日志中可能包含 IP，报告时匿名化。
3. 对当前线上站点分别检查 HTTP/HTTPS、带/不带 www、根路径、301/302 Location、Content-Type、canonical、robots、页面原始 HTML 和 CDN cache header。当前检查不能替代历史状态的取证。
4. 若无法归因：向 Bing Webmaster Support 提供曲线断点、已索引及 Live 检测截图、Indexed HTML、主要查询词日期对比和服务器日志摘要，询问搜索展示/报告异常。

**核算**：09-10—09-16 共 88 条，日均 12.57；09-17—09-20 共 6 条，日均 1.50，约下降 **88.1%**。请求路径仅首页 `/`，另有数次 `/robots.txt`，没有其他业务 URL；全部精确状态码是 200 或 304，**没有 301/302，也没有 403/404/429/5xx**。304 是规范的缓存重新验证响应，不应当成抓取失败。HTTP 200 也证明当时源站有实际响应。

**与 Bing 搜索数据交叉**：网站维护者提供的近 30 天 Search Performance 截图显示 **12 clicks / 362 impressions / 3.31% CTR**，查询表中曾有“退休金测算”“退休工资计算器2026”等历史位置约 8–11；曲线在 09-16 左右突然接近 0。Bing Webmaster 当日对首页显示 **Indexed successfully** 且 **Live URL can be indexed by Bing**，SEO/GEO 检查没有报告索引技术问题。故抓取频率骤降与搜索曝光消失存在明显时间相关，但**无法仅凭这份日志判断原因与结果先后或算法机制**；上述平均排名不是最新排名。

**严格边界**：

1. 源站 access.log 只记录成功到达 Nginx 的请求；**不能排除 Cloudflare 在边缘层阻止、挑战或未转发的请求**。需 Cloudflare 对应时段日志才可排除这一路径。
2. 日志按照 User-Agent 字符串匹配，**无法证明 94 条记录都是已验证的 Bingbot**。如需进一步确认，应使用 IP 反向 DNS + 正向解析或 Bing 官方爬虫验证程序；暂时以 *Bingbot-UA* 表述。
3. 没有历史爬虫实际取得的网页正文、响应头缓存校验细节或服务器部署操作时间，故不能认定 PR #9 首页首屏改写造成 Bing 抓取骤减；也不能反过来认定 Bing 算法故障。
4. 2026-10-09 上线时发生的 Nginx 403 权限回归**晚于 09-16 事件**；已修复，不能拿它解释九月的历史曝光断崖。
5. 报告原有“缺少 Bingbot 历史访问日志”的限制**现在对当前这段日期汇总已补齐**，但没有真实 IP 验证/CDN 边缘日志/按查询按日历史排名，根因继续标记 **UNCONFIRMED**。

**推荐下一步优先级**：停止重复抓取脚本和盲目提交 URL。第一优先向 Bing Webmaster **Search Performance** 导出 **09-01—09-15 与 09-16—09-30** 分日期、Pages/Queries 的 impressions、clicks、average position（按同一 Web 流量范围），确认是查询排名/展示消失还是报告异常；若两侧对比和站点索引均无法解释，准备现有取证材料向 Bing Webmaster 支持提交案例。Cloudflare 9 月历史请求审计仅在可获得边缘日志时作为并行辅助，不应再要求大量命令逐项试错。

**数据质量红旗：第二份关键词 CSV `yanglao.zhibeimao.com_PageTrafficReport_10_9_2026.csv` 含 25 行，列名为 `Last Impressions`/`Prev Impressions` 等。其中历史列合计 `Last Impressions=586`、`Prev Impressions=422`、`Last Clicks=18`、`Prev Clicks=14`；单个查询“养老金计算器”的 Prev Impressions 为 186、Prev Clicks 为 7。与 Pages 同时段**全站后半月总曝光 22、点击 0** 完全不相容。两份 CSV 不能据此直接联表、拆解前后关键词排名。极可能是导出时页面状态/筛选日期不同，或 Bing 导出数据异常；CSV 没有日期元数据，不可臆断哪一种。此前对关键词来源和平均排名的推断只限有明确截图的对应窗口；不能用这份关键词文件给出“哪些词后半月保住排名”结论。

**证据等级的更新**：
- **确证**：指定 Pages 视图首页 1537 → 22 曝光、37 → 0 点击（-98.57%），已索引且 Live 可索引；2026-09-10—20 Bingbot-UA 源站请求只有 200/304，09-17 起明显减少。
- **排除/削弱**：全站页面曝光转移、当时普遍源站 403/5xx、当前 deindex/noindex。
- **未确证**：实际 Bingbot 身份、Cloudflare 边缘被拦截或挑战的请求、Bing 内部 search-serving/算法机制、哪个搜索词的实际排名掉出结果、当年 9 月发布内容与掉量之间的因果关系。
- **决定**：停止重复服务器日志采样、IndexNow 提交和生产 SEO 改动；要求如需关键词层因果分析，先从**同一 Compare 筛选条件、选中 Keywords 标签之后**重新下载，核对关键词样本的合计是否合理。若仍不相容，将“关键词与页面导出不一致”与曝光异常**一并报 Bing Webmaster 支持**。向支持说明历史抓取统计是基于 UA 匹配而非官方验证 IP。
